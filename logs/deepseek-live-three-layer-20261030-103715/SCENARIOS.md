# SSE 场景验证索引

本目录是已核对的真实调用和离线回归样本，随 SSE 模块提交。每个场景使用独立目录和日志。此轮重新请求 DeepSeek 官方接口，三层记录均在本轮请求过程中生成。本轮重新运行时未覆盖旧日志；随后按用户要求清理未被本索引直接引用的日志文件。

| 验证 | 结果 |
|---|---|
| DeepSeek 真实请求 | 14/14 通过，合计 1815 token |
| 离线边界及故障注入 | 54/54 符合预期 |
| 清理前旧日志核对 | 本轮重跑时，原有 1092 个文件 SHA256 未变；未引用文件现已清理 |
| 三层对象一致性 | 12 份真实 SSE 的结果、参数、usage 及本地回放均核对通过 |

真实请求使用 `deepseek-flash`，包括 Chat Completions 和 Responses。每种协议覆盖文本、JSON、单工具、双工具、长度上限、思考模式和无效模型 HTTP 错误。工具只声明和解析，没有执行真实天气查询；双工具实测参数包含上海和北京。

| 层 | 文件 | 内容 |
|---|---|---|
| 第一层 | layer-1-sse.jsonl | 每条完整 SSE 的上游 JSON；event_index 从 1 开始，原 sequence_number 保留在 object 内 |
| 第二层 | layer-2-result.json | 跨事件合并的对象、事件序号范围、complete/partial 和错误 |
| 第三层 | layer-3-events.jsonl | 统一业务事件：文本增量、工具开始/参数增量/完成、usage、结束或错误 |
| 完整日志 | events.jsonl | 本轮生成的三层交错记录 |
| 最终对象 | result.json | 业务代码返回的 ChatResult / ResponseObject |

第一层直接嵌入上游 JSON，保留未知字段及缺省状态。Chat 的 `[DONE]` 使用 data 字段保留。SSE 解帧之前的半截事件、非法 UTF-8 和行超限无法形成完整事件，所以第一层可能为空；可通过 input.sse 稳定复现。第三层通过 event_index 关联触发它的第一层；工具完成事件带起止序号范围。usage 是整次请求的快照，不按工具或事件相加。

HTTP 错误使用 http_error 记录，不会生成三层 SSE 对象，表格以“不适用”标注。Chat length 表示协议正常结束但生成截断；Responses length 的 incomplete 保留 partial 和统一 error 事件。日志写入失败场景中的缺失层是预期结果，不补造数据。

这是一份有限场景矩阵；拒绝、断流、非法索引等通过离线注入稳定复现，没有算作真实模型输出。旧矩阵的 parsed 写失败改为第一层 sse 写失败，并新增两种协议的第三层 event 写失败，离线场景由 52 个增至 54 个。

## 复现

在模块目录执行；输出目录必须不存在。第一条会重新产生 14 次真实 API 请求，第二条只运行离线输入：

```sh
go run ./cmd/deepseek-examples -key-file /private/tmp/deepseek-api-key.txt -out logs/deepseek-live-three-layer-new
go run ./cmd/deepseek-examples -offline -out logs/offline-three-layer-new
```

本轮沿用原场景文档结构并增加三层对象列。日志目录已按本索引的直接文件链接清理，历史索引与未引用样本已移除。
